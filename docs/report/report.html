This report documents a one-to-one translation of a browser game into a native engine. The ANITS College web build is a third-person campus life-simulator whose entire state — plan geometry, NPC roster, dialogue, economy, mission script — is already tabulated as data. The port therefore treats the work as a translation problem rather than a design problem: every coordinate, radius, price and line of dialogue in the Godot build is copied from the original's own source files, and the campus is generated from src/data/campus_data.json so that the plan can change without touching a line of GDScript.

All figures in this report were read from the shipping source of both projects. No measured frame-rate numbers are claimed; benchmark slots are marked <!-- BENCH: --> and left empty on purpose.

01 · Executive summaryWhat was built, and how it was verified

The ANITS College web game — a third-person campus life-simulator built on Three.js — has been re-implemented as a native Godot 4.7 project. The Godot build boots into a recreated front end, generates the entire ANITS campus procedurally from a single JSON plan file, spawns all 64 non-player characters with their original dialogue, and plays the complete Day 1 mission chain from the gate to the Colonel's parade ground.

The porting thesis

The original build is unusual in one respect that shaped the whole effort: almost none of its content is authored in code. The campus plan is three arrays of rectangles (BLD, ROADS, SAND, BASK, NCC); the NPCs are a compact table that the original expands at runtime; the missions are arrays of step objects; and the dialogue is a dictionary keyed by step index. Reading those tables and re-emitting them is the port.

The Godot build keeps that shape. src/data/campus_data.json holds the campus in plan pixels — the same coordinate system the web build used — and src/util/campus.gd converts plan pixels to world metres at load time (1 plan px = 0.7 m, origin (215, 250)). Because the conversion lives in exactly one place, changing the campus is a JSON edit, never a code edit.

What the translation looked like in practice

  • Geometry. src/world/campus_builder.gd walks the JSON and emits the ground, the streets, the kerbs, the zebra crossing, the perimeter walls, the hinged main gate, the building masses and every prop. Repeated props become MultiMeshInstance3D batches, so a species costs one draw call per surface.
  • Characters. The original glTF/FBX models were imported from third_party/anits_original/ and fitted into their plots by src/world/original_models.gd, which reproduces the web build's own per-model scale factors rather than normalising them.
  • Script. src/autoload/mission_runner.gd holds the Day 1 steps as a constant array with the same field names the original used (text, npc, line, pos, radius, type).
  • Audio. src/autoload/voice_bank.gd replays the original's own 632 MP3 recordings, matched to the line text through clips.json (340 lines) and clips_girl.json (310 lines), and reuses the original per-character pitch/rate profiles.

Translating the Admin Block

The Admin Block is the one building whose interior the player enters, so it needed both an exterior and a collision model that leaves a corridor open. campus_builder.gd reproduces the web build's arrangement exactly: the imported b_admin.fbx is placed at scale 0.98, then the two solid wings are re-created as box colliders (AdminWestWing, AdminEastWing) that span the model's inner-to-outer extent, so the player can walk through the middle but not into the walls. The devotional statue and the two porch columns get their own small colliders.

The office itself is a separate node (src/world/admin_office.gd) built far west of the campus at CENTER = (−320, 0, 0) and reached through an invisible interact target named AdminOfficeHallDoor in the group's admin_office_door. The mission marker is retargeted to the hall door rather than to Laksmi while the player is outside, because Laksmi is sealed inside the room — see §8.

Why the palette trick matters The original low-poly pack bakes every building into a single 256 × 256 palette atlas. The web game recolours one 32 × 32 swatch per building to get a different wall colour while keeping the roof, window and door colours intact. The Godot build reproduces this in _palette_texture(), caching one ImageTexture per colour — which is why the peach IT block and the sandy CSM block read correctly rather than as flat coloured boxes.

The model-fitting rule

src/world/original_models.gd keeps two fitting modes. The fixed mode uses the web build's own literal factor — the Admin Block at 0.98, the auditorium at 1.6, the bench at 0.286, the temple at 11.0 — because those factors were already tuned against the original's scene scale. The fit mode scales a model so its footprint fills the plot rectangle, and is used for the bank, café, workshop, auditorium pavilion and the classroom-panel block. The height mode normalises a character to a target stature: the guard 1.7 m, Laksmi 1.7 m, cadets 1.7/1.62/1.6 m, Colonel Singh 1.85 m, Remy 1.75 m.

Salute mechanics

main.gd::_salute() mirrors the web build's rule: pressing G plays the player's salute animation, and if the player is within 20 m of Colonel Singh — or the current step is of type salute — the colonel returns the salute and the cadet company answers, each cadet offset by 0.11 s so the formation ripples rather than snapping. When the active step is a salute step, the mission advances and the toast "The NCC company returns your salute. Jai Hind!" is raised.

Difference in formation layout The web build draws the parade company as a loose hand-built formation. The Godot build expands the same 3 × 6 grid from the cadets block of npcs.json (rows: 3, cols: 6, with row_step and col_step), producing 18 cadets at deterministic positions — the same approach the web build's own table expansion used, and the reason the headless suite can assert the count.

Gates and walls

Six wall runs enclose the campus, each 2.4 m high with a capped coping and stone pillars every 12 m. Two gates pierce them: the main gate at plan [100, 432, 145, 432] — two 8.2 m stone pillars, a lintel carrying the ANITS sign in gold and the college's full name beneath it, and two barred leaves that swing open to 78° once the guard has been spoken to — and the Back Gate arch at plan (236, 98), a blue 9 m portal labelled Back Gate.

How the campus is generated

Nothing about the campus is hand-modelled. campus_builder.gd walks the JSON in a fixed order — ground, roads, zones, walls, gates, buildings, specials, props, lamps, benches, vending machines — and emits the geometry, the materials and the collision shapes from it. The only hand-written geometry in the whole campus is the Admin Office, because it is the one room the player can walk into. This is what makes the plan portable: a different campus is a different campus_data.json.

Two coordinate spaces are in play. The plan is authored in plan pixels and converted once, at load time, into world metres. The authored data is therefore directly comparable with the web build's own tables, which is what the headless suite asserts (§11.1).

04 · Campus layout & roadsThe perimeter road and the campus landmarks

The web build's campus sits inside a boundary wall with no road beyond it. The port keeps that wall but adds a perimeter road that rings the whole compound, because the brief asks for roads all the way along the college and because a real campus has a service road outside the gate. The ring is narrow — 9.8 m — and runs between the wall and the grass verge, so it frames the campus instead of cutting through it. The main-gate driveway and the central north–south street both meet it, which makes the gate, the back gate and the parade ground reachable by car.

Every road rect uses a single unshaded asphalt shader with painted edge lines and dashed centre lines. The material is two-sided (cull_disabled), so the surface stays solid from the aerial camera and from the low camera boom instead of disappearing when a quad is viewed from behind — the bug that made the compound read as grass and footpaths in an earlier build.

Character rendering and culling

src/world/character_visual.gd normalises each imported model to a target height, finds its AnimationPlayer and exposes walk, idle, talk and salute clips. Walk cycle

The imported Mixamo walk travels forward on the hips track, so playing it unmodified slides the character across the ground and snaps back on loop. The port bakes every hips position track in place — X and Z pinned to the first key, the vertical bob kept — exactly like the web build's v[i*3]=v[0]; v[i*3+2]=v[2]. The removed distance is kept as the cycle's stride, measured once per model and cached (boy 1.31 m, Amy 1.24 m, Remy 1.40 m). Playback is then driven by clamp(speed / stride, 0.45, 3.2), the same formula as js/game.js, so the feet stay planted at every speed. Because the character files contain no run clip, a run plays the same cycle faster and leans the body 0.12 rad into the direction of travel.

The target is 60 fps, capped in code by Engine.max_fps = 60. This section describes how the frame is budgeted and which levers exist. It deliberately contains no measured frame-rate figures — the benchmark slots are marked and left empty.

Sky, sun and atmosphere

The sky is the Sky3D addon (res://addons/sky_3d/), which owns the sky dome, the atmosphere, the clouds, the sun, the moon and the time of day. What the mobile path costs

  • Rendering at 78 % of the screen and upscaling bilinearly — the most significant single saving, and the least noticeable at arm's length on a phone.
  • If the frame rate still drops below 58 fps for three seconds, the scale steps down (68, 58, 50 %) and finally the sun shadow is turned off, so the game degrades instead of stuttering.
  • Halving the shadow map and halving the shadow distance removes most of the shadow-pass cost on tile-based mobile GPUs.
  • Disabling the cumulus layer removes the most expensive part of Sky3D; the cirrus layer stays so the sky is not empty.
  • Shortening the fog end distance lets the horizon dissolve earlier, so less of the campus is ever rasterised.
